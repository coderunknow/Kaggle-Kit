# Kaggle-Kit v0.1.0-dev7 — development candidate

**Status:** unpublished development candidate. No tag or release is created
by this work; the pull request stays in draft (see "Not live-verified").

- **Intended version:** `0.1.0-dev7`
- **Source commit:** `{{SOURCE_SHA}}`
- **Compatibility:** existing profiles, conversations, credential modes,
  retention defaults and advanced integrations keep their stored formats.
  The verified Qwen T4 x2 deployment is behaviour-identical, including its
  server-reuse fingerprint (proven by test), so an upgrade never restarts a
  healthy Qwen server or rotates its key by itself. New sampling fields are
  absent on old profiles and stay unsent until configured.

## Implemented

- Ordered first-run connection guidance and endpoint-type help, preserving
  the effective normalized URL, optional model authentication and actual
  inference verification. Empty discovery now explains manual model entry.
- Basic/Advanced views without resetting unsaved or existing advanced
  values. A connected active profile offers Start chatting.
- Explicit reviewed keyless built-in grant (Save required) with presets
  that only narrow the allowlist; the native tool probe stays mandatory.
- **Model catalog** (Qwen3.8-27B, Raon-1 mini preview, custom endpoints):
  browsable in the profile editor with architecture/access metadata,
  per-combination deployment statuses with evidence, and discovery-based
  availability. Selecting an entry edits drafts only — it never installs,
  starts or switches a remote model, and a missing model is reported with
  the way to launch/configure the matching deployment.
- **Raon-1 mini preview**:
  - GPU T4 x2 deployment in the same cell (`KAGGLE_KIT_MODEL=raon`):
    KRAFTON llama.cpp branch built from pinned commit `fb895662...`,
    official GGUF pinned by revision `fe24f24e...` and per-file SHA-256,
    evidence-based quantization selection (Q4_K_M on T4), gated download
    via `HF_TOKEN`/hub login (header to huggingface.co only, explicit
    failure without authorization), served alias, model-card startup
    sampling, real-inference smoke test, own state/key/runtime bundle.
  - Model-specific sampling end to end: temperature 1.0, top-p 0.95,
    top-k 20, min-p 0.0, repetition penalty 1.0, frequency penalty 0,
    presence penalty 1.5 (general) / 0 (coding-math), applied per profile
    from the catalog; `top_k`/`min_p`/`repetition_penalty` are new opt-in,
    clamped fields that are omitted entirely when unset.
  - Hosted Raon API as an ordinary separate profile: configurable
    endpoint/credential (nothing hardcoded, no endpoint invented),
    discovery plus the staged real-inference connection test. The hosted
    service's terms are the provider's, separate from the Apache-2.0
    weights.
- **Qwen3.8-27B on TPU v5e-8** (`notebooks/tpu_deployment.py`): official
  bf16 checkpoint at pinned revision `1d4bf0f2...` via `vllm-tpu==0.28.0`,
  tensor-parallel 8, `PJRT_DEVICE=TPU`, runtime-generated key via
  environment only, verified auth enforcement, real-inference smoke test,
  same ownership/reuse rules and pinned tunnel. Eight detected TPU devices
  are required; MTP is refused with the documented corruption reason.
- **Raon on TPU is explicitly blocked** with evidence (no TPU kernels for
  `raon1`; GGUF/CUDA-only vendor paths) and refuses before installing
  anything — never a CPU/GPU/hosted fallback in TPU clothing.
- Tool-calling/streaming fixes, each reproduced by a failing test first:
  vLLM-style streamed `delta.reasoning` is kept separate from content;
  conflicting streamed tool-call id/name on one index can no longer merge
  two calls; aborting a silent SSE stream now actually wakes the pending
  read (and a cancelled stream yields no trailing partial event). The
  deterministic mock and the built-bundle integration check cover the
  reasoning channels end to end.
- Earlier candidate fixes retained: stale green editor tests after a key
  change, 12 s whole-operation deadlines for public-web operations,
  malformed Brave payloads as provider-format errors, cancelled Docker
  requests refused before spawn.

## Not live-verified (why the PR stays draft)

No Kaggle GPU/TPU session, gated Raon access, hosted-provider credential,
Docker runtime, or local Playwright browser was available in the
development environment. Therefore:

- Raon on T4 x2 and Qwen on TPU v5e-8 are **implemented, not live-verified**.
  `docs/kaggle-deployment.md` section 12 is the exact operator procedure
  (including negative checks) that produces the missing evidence. No
  speed/memory/startup number for these paths is claimed anywhere.
- No live model (Qwen, Raon, or hosted) executed here: tool-calling and
  benchmark evidence is the deterministic mock plus unit/integration
  suites, with synthetic tool results labelled as protocol evidence only.
- Playwright e2e could not run locally (browser download host
  unreachable); the CI Browser job on the final head is the path.

## Deferred by evidence

- **Keyless public-web search:** reassessed 2026-10-22 from primary
  sources (SearXNG public-instance format/authorization limits,
  DuckDuckGo has no web-search API, Marginalia's shared experimentation
  key + CC-BY-NC-SA results license, candidate hosts unreachable from the
  sandbox). No provider met the bar, so nothing ships and nothing is
  advertised; page retrieval is not search and optional Brave still needs
  its own key. Full analysis: [dev7 audit](../dev7-audit.md).
- **Browser Python:** still deferred — no proven isolation boundary or
  authenticated browser-result bridge; digest-pinned, approval-gated
  Docker remains the only code path.
