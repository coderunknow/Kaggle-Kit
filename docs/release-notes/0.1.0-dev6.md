## Summary

`0.1.0-dev6` is a tool-calling reliability, context-budget, and security hardening development release built from `main` after `v0.1.0-dev5` and PR #11 (`ad7995b`):

* **Capability detection & empty `modelId` parity:** `ProxyService.probeToolCalling` raises its per-turn token budget to `192` tokens so reasoning-enabled models (`--reasoning-effort medium`) do not truncate inside `<think>` before emitting `finish_reason: "tool_calls"` or `KAGGLE_KIT_TOOL_PROBE_OK`, records `protocolVerified` and `roundTripVerified` on `ToolCallingCapability`, and preserves cached `toolCalling` across `detectCapabilities()` / connection tests when the profile identity has not changed. `/api/tools/capability`, `/api/tools/chat`, and `/api/proxy/probe-stream` now auto-discover the first model from `/v1/models` when `profile.modelId` is empty (`"first model of the server"`), matching `/api/proxy/test` and `/api/proxy/chat`.
* **Bounded 1-attempt corrective recovery:** `ToolChatService` allows at most **one** corrective model retry per failed tool-selection or argument-generation episode — covering unknown/disallowed tool names (`invalid_tool_name`), malformed JSON or schema violations (`invalid_arguments` with `summarizeToolSchema()` guidance), and Round-1 missed tool calls (`raw_tool_markup_in_prose`, `contradictory_no_tools_refusal`, `uninspected_conversation_upload`, `unfetched_explicit_url`). Corrective retries count against round/call/timeout budgets, never fabricate results, never bypass user denials or approval gates, and terminate immediately if the single retry also fails validation.
* **Context-window catalog budgeting (`measureToolCatalog`):** Tool definitions are compacted, filtered for per-turn runtime readiness (omitting `files_read` and `files_analyze` when a conversation has zero uploaded files, and reporting `missing_provider_config`, `missing_secret`, `sandbox_disabled`, or `mcp_not_granted`), and capped at `MAX_TOOL_CATALOG_BYTES = 12,000` UTF-8 bytes (`MAX_ACTIVE_TOOLS_PER_TURN = 16`) so tool schemas fit comfortably inside the 8,192-token target context window.
* **Prompt consistency & turn diagnostics (`ToolTurnDiagnostics`):** `neutralizeNoToolsClaim()` strips no-tools claims across all prompt variants on tool-enabled turns, while `neutralizeToolClaimsForOrdinaryChat()` restores the truthful no-tools boundary when `qwenToolSystemPrompt()` is used on an ordinary chat turn without tools. Every tool-chat response attaches `toolDiagnostics` (turn outcome, active and omitted tools, serialized byte/char/estimated-token budget, rounds and calls used, and corrective retry outcome) and preserves both unique trace `id` and model wire `callId`.
* **Approval & lifecycle cleanup:** Expired or failed approval requests in `useChat.ts` are marked `expired`/`denied`/`stale` rather than `approved`. Deleting a profile, deleting/clearing a conversation, resending/editing/retrying a message, or starting a new turn in the same conversation cancels stale pending `ToolChatJob`s and cleans up conversation file vaults.
* **Real-model & application integration benchmark CLI (`tools/benchmark-tool-calling.mjs`):** Adds `npm run benchmark:tools` with two explicitly separated phases (`--mode model` and `--mode integration`), environment/prompt-only credential handling (rejecting `--api-key` on the command line with exit code 2), automatic secret/tunnel redaction, and multi-trial pass/recovery reporting.
* **Kaggle deployment script hardening (`notebooks/qwen3_8_27b_api.py`):** Pins `cloudflared` release versions (`2026.10.2`, `2026.10.1`, `2026.10.0`) with SHA-256 verification (`CLOUDFLARED_SHA256`), enforces `--api-key-file` by default on real server launches (`allow_cli_api_key_fallback: False`), adds `model_revision` and `model_sha256` support, terminates timed-out `cloudflared` processes, and fixes `applied["unsupported_options"]` reporting on fresh starts.

## What was verified

* TypeScript type checking of the browser client and the backend (`npm run typecheck`).
* ESLint over the TypeScript and React sources (`npm run lint`).
* Unit, component, policy, security and integration tests (`npm test`).
* Production build of the client and the backend bundle (`npm run build`).
* End-to-end integration check against the built bundle and the mock OpenAI-compatible server, including streaming, cancellation, request origin and content-type policy, bundled PDF/DOCX extraction, native tool capability probing (including streamed tool-call fragments), automatic read-only calculator execution, bounded 1-attempt corrective recovery, and single-use code-execution approval/denial (`npm run check:integration`).
* Two-phase tool-calling benchmark CLI (`npm run benchmark:tools -- --spawn-mock`) across all 6 model-only scenarios (12/12 trial samples) and all 11 application-integration checks.
* Browser E2E suite in headless Chromium against the built bundle (`npm run test:e2e`).
* Unit tests of the Kaggle deployment script, including SHA-256 verification of `llama.cpp` and `cloudflared` release assets, `--api-key-file` enforcement, `model_sha256` verification, and safe archive extraction (`python3 -m unittest discover -s notebooks -p "test_*.py"`).
* Unit tests of the release validator and the check runner (`python3 -m unittest discover -s tools -p "test_*.py"`).

The exact commands, their durations and their exit codes are recorded in `verification-report.json`.

## What was not verified in CI

* A live run on a Kaggle T4 x2 session with `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf` and a live Cloudflare Quick Tunnel (`npm run benchmark:tools` without `--spawn-mock` requires an operator-supplied live endpoint and API key).
* Real Brave Search API requests (requires a user-supplied Brave Search API key) and real remote MCP servers.
* Live Docker container execution in environments without a running Docker daemon.
* Native execution of `tools/check-kaggle-connection.ps1` on a Windows host with PowerShell.
