# Kaggle-Kit v0.1.0-dev6

**Status:** development prerelease — remediation and validation release for
tool-calling reliability.

- **Release tag:** `v0.1.0-dev6` (not yet published at the time of writing)
- **Source commit:** `{{SOURCE_SHA}}` (the exact commit this release was built from)
- **Compatibility:** ordinary chat, profiles, conversations, tool settings and
  stored histories from v0.1.0-dev5 are preserved unchanged. New optional
  fields (`selectionRecovery` in conversation tool settings, `recovery` and
  `contextNotice` in tool-chat results) are additive; older clients and stored
  conversations keep working. One intentional deployment behaviour change: the
  Kaggle notebook no longer passes the API key as a `llama-server` command-line
  argument in the fallback path (see below), and `cloudflared` is now fetched
  from a pinned, digest-verified release instead of `releases/latest`.

## Why this release exists

The dev5 state could not demonstrate that the **live deployed model** reliably
selects and executes tools, and the tool loop had no bounded way to recover
from a model turn that was protocol-invalid or argument-invalid. This release
(a) repairs and hardens the tool-call lifecycle, (b) makes every failure layer
distinguishable in the UI and in results, and (c) ships an executable
live-model benchmark so the operator can prove — with their own endpoint and
credentials, without sharing them — which layer actually fails.

## What changed

### Bounded corrective recovery for tool calls (`server/tools/chat.ts`)

- **Protocol-invalid turns never execute and get one corrective round.** When
  the endpoint returns tool-call data with a wrong `finish_reason`, or only
  malformed calls, nothing runs. The loop spends at most **one corrective
  attempt per correction episode**: the model receives the exact failure
  evidence and the valid tool list for the turn. A second failure in the same
  episode ends the loop with an honest report; results are never fabricated.
- **Invalid arguments / unknown tools get exactly one corrective feedback.**
  The validation error is returned to the model as the tool result (its single
  corrective opportunity). An identical invalid call repeated — or any second
  invalid call in the same episode — ends the loop truthfully instead of
  cycling.
- **Episodes reset on successful execution**, so a later, unrelated failure
  gets its own single attempt. All corrective rounds count against the
  existing round/time budgets and can never bypass an approval, a denial, an
  unavailable service or an exhausted budget.
- **Opt-in selection recovery.** Conversation tool settings gained
  `selectionRecovery` (UI toggle "Allow one corrective round when the model
  answers without considering the tools", off by default): when the first
  model round of a turn answers with plain text and no tool ran, at most one
  extra round asks the model whether a listed tool is actually needed. The
  model may still answer directly, so ordinary questions are never forced
  through a tool and no keyword heuristics are involved.
- **Recovery is visible.** Tool-chat results carry a `recovery` record
  (attempts, outcome `corrected`/`failed`, secret-free event evidence); the
  chat UI shows it as a message note so the timeline never implies a smooth
  run when a corrective round happened.

### Tool-catalog context budget (`shared/tools/catalog.ts`, tool chat)

- The exact serialized byte size of the tool catalog sent with every round is
  now measured (`measureToolCatalog`). Catalogs above **16,000 bytes** are
  refused with an actionable HTTP 409 (previously a single large
  user-configured HTTP/MCP schema could silently consume the documented
  8192-token context). Above **6,000 bytes** the result carries a truthful
  `contextNotice`, surfaced in the chat. Token figures are labelled estimates
  derived from bytes (÷3.6, matching the existing prompt estimator) — never
  tokenizer counts. Measured reference: the full nine-tool built-in catalog
  is 3,728 bytes (~1,036 estimated tokens).

### Live-model benchmark (`tools/model-benchmark.mjs`, `tools/model-benchmark-core.mjs`)

- New executable diagnostic for the operator's **real** OpenAI-compatible
  endpoint. Model mode verifies: the harmless two-step native tool-call
  handshake; tool **selection** on an unambiguous task (calculator vs. a web
  distractor); **argument** correctness against the published schema and the
  expected semantics (`17*23+101 = 492`, evaluated by a deterministic
  no-eval parser); honest acceptance of a clearly-marked **synthetic** tool
  result with a final stop answer; a **negative** case (an ordinary question
  must not trigger tools); and optional streamed tool-call fragment
  assembly. Endpoint rejections (HTTP 400/404/422 on tool requests) are
  classified as **blocked/unsupported**, distinct from a model that speaks
  the protocol but fails behaviourally.
- Integration mode (`--mode integration`) exercises a running Kaggle-Kit
  proxy end to end: capability probe, automatic calculator run through the
  real tool loop, and the Python approval path — always **denied**, never
  approved, by the benchmark. Missing preconditions are reported as
  **skipped**, never as passed.
- Security: credentials come from the environment (`OPENAI_API_KEY` /
  `KAGGLE_KIT_MODEL_API_KEY`) or a masked interactive prompt; `--api-key` on
  the command line is rejected. Reports contain only a sanitized endpoint
  identity (scheme/host/path), the key's length, model ID, timestamps,
  request settings, per-case outcomes with reasons, sample counts and scores,
  and the five evidence layers (`protocol`, `selection`, `arguments`,
  `execution`, `end_to_end`) kept strictly apart. A final leak check refuses
  to emit a report containing any known secret value.
- Multiple trials are supported (`--trials`, default 3); the report states
  sample counts and observed scores and explicitly disclaims statistical
  significance. Usage and interpretation are documented in the README and
  `docs/troubleshooting.md`.

### Kaggle notebook hardening (`notebooks/qwen3_8_27b_api.py`)

- **API key never on argv.** The `llama-server` start-up used
  `--api-key <key>` as a fallback when `--api-key-file` was unsupported,
  exposing the key in `/proc/<pid>/cmdline`. All three pinned builds
  (b11717–b11719) were verified against their published sources
  (`common/arg.cpp`) to support `--api-key-file` **and** to read `--api-key`
  from the `LLAMA_API_KEY` environment variable. The fallback now injects
  `LLAMA_API_KEY` into the server process environment instead of argv, and a
  build that supports neither mechanism is refused instead of starting an
  unauthenticated (potentially tunnel-exposed) server.
- **`cloudflared` pinned and digest-verified.** The tunnel binary was fetched
  from the moving `releases/latest/download` URL. It is now pinned to release
  `2026.10.2` and verified against the SHA-256 digest Cloudflare published
  for `cloudflared-linux-amd64` (retrieved via the GitHub releases API);
  existing files are reused only when they match the pinned digest. The
  Hugging Face model fetch still uses `resolve/main`: no authoritative digest
  is reachable for it from this environment, so pinning it remains a
  documented residual risk rather than a guessed change.

### Verification expansion

- The mock upstream can emit a protocol-violating turn (tool-call data with
  `finish_reason: "stop"`), and the built-bundle integration check grew from
  28 to **29 checks**, proving the bounded corrective recovery end to end
  against the built application.
- New/updated regression tests cover: corrective rounds after inconsistent
  `finish_reason` and malformed calls; budget exhaustion without recovery;
  repeated and second invalid calls ending the loop; episode reset after a
  successful execution; opt-in selection recovery (success, second direct
  answer, once-per-job); catalog hard-cap refusal and context notice; the
  benchmark's credential hygiene (argv rejection, endpoint sanitization,
  report leak check), scoring (skipped/blocked never counted as passed),
  layer separation, the deterministic expression evaluator, streamed
  fragment assembly; and the notebook's env-var key fallback, unauthenticated
  build refusal and cloudflared pinning.
- All dev5 security protections remain covered by their existing tests and
  were re-run green: workflow shell-injection tests, DNS-pinned fetch,
  origin policy, sandbox container cleanup contract, credential-fingerprint
  approval binding, symlink escape refusal, notebook checksum logic.

## Not verified / limitations

- **No real-model evidence yet.** No live Kaggle endpoint, deployed model or
  public tunnel was reachable from this environment. The benchmark proves the
  *script*; the operator must run it against their endpoint before claiming
  improved real-model behaviour. Mock and unit tests prove application
  behaviour only.
- Docker remains unavailable here; the Python sandbox contract is covered by
  unit tests and the real-Docker CI job, not by a local run.
- The integration benchmark mode was not run against a fully configured live
  proxy+endpoint pair (no endpoint exists here); its skip/failure paths were
  exercised.
- No Brave account, live MCP server or external configured HTTP service was
  exercised; missing-credential and failure paths are test-covered.
- The Hugging Face model download remains on the unpinned `resolve/main`
  revision (documented residual risk; pinning requires live-environment
  evidence).
- The `LLAMA_API_KEY` environment fallback is verified against the pinned
  builds' published sources and unit-tested at the command-construction level;
  it was not exercised on live Kaggle hardware.
- Playwright e2e runs in CI only (see above); no assistive-technology audit.
