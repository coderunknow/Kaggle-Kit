# Kaggle-Kit v0.1.0-dev5

**Status:** development prerelease.

- **Release tag:** `v0.1.0-dev5`
- **Source commit:** `{{SOURCE_SHA}}` (the exact commit this release was built from)
- **Compatibility:** ordinary OpenAI-compatible chat, profiles, conversations and tool settings from v0.1.0-dev4 are preserved. One intentional behaviour change: when the app is served through a non-loopback name (for example a LAN hostname), that origin must now be listed in `KAGGLE_KIT_ALLOWED_ORIGINS`; loopback access (`127.0.0.1`, `localhost`, `[::1]`) is unchanged.

## What changed

This release is the result of a full repository audit and remediation pass over v0.1.0-dev4. No features were redesigned; every change fixes a confirmed defect or closes a verified gap.

- **Release workflow shell injection removed (critical).** The release and CI workflows no longer interpolate `${{ }}` expressions into shell source. The user-supplied release tag reaches the shell only as data through an `env:` variable, is validated against the full version format before any path, Git or publish use, and the checked-out commit, `package.json` version, release notes, manifest and checksums must all agree before publication. All actions are pinned to full commit SHAs and job permissions are least-privilege. Regression tests (`tools/test_workflow_security.py`) prove hostile tags cannot execute shell, alter step outputs or influence the release before validation.
- **DNS-rebinding protection for the model proxy.** Every server-side upstream request (non-streaming and streaming chat, model listing, capability and streaming probes, tool rounds) now connects through a DNS-pinned fetch: the complete DNS answer is validated before the socket is dialled, with TLS SNI/Host unchanged. Names resolving to link-local/cloud-metadata addresses are always refused, public names resolving to loopback are refused as rebinding attempts, and `KAGGLE_KIT_BLOCK_PRIVATE_NETWORKS=1` refuses any private answer. Literal local endpoints (`127.0.0.1:8000`) and, by default, LAN hostnames keep working. The non-streaming chat path also gained the redirect destination validation it previously skipped.
- **Origin policy hardened.** A browser origin is only trusted automatically when the request arrives through a loopback `Host`; a DNS name that resolves to this machine can no longer present itself as its own origin. Non-loopback serving origins require `KAGGLE_KIT_ALLOWED_ORIGINS`.
- **Sandbox containers can no longer outlive their run.** Python sandbox runs use named containers and force-remove them on timeout, cancellation, output overflow and Docker errors; previously only the Docker CLI was signalled, which a SIGKILL cannot forward, so a stopped program could keep running. The program is also fed on stdin instead of as an argv element, so it never appears in host process listings.
- **Approvals are bound to credential values.** Rotating a secret (Brave key, HTTP-tool or MCP header credential) while an approval is pending now invalidates that approval (HTTP 409, job discarded); previously only settings *references* were compared, so an approved call could execute under a different credential.
- **Approvals describe the concrete operation.** The approval card now shows an operation-specific summary (for example `Send POST request to https://…` or `Run Python code in the sandbox (128 characters): print(1)`) and displays the bounded arguments expanded, instead of a generic tool description behind a collapsed section.
- **Static file serving refuses symlink escapes.** The built client is served only when the canonical path stays inside the client directory.
- **Notebook downloads are integrity-checked.** The Kaggle deployment script verifies the official llama.cpp release assets against pinned SHA-256 digests (as published by the GitHub API) before extraction; a mismatch deletes the file and aborts without executing anything. API-key and server-state files are created owner-only (`0600`) from the first byte.
- **Smaller initial bundle.** Settings and the Markdown renderer are lazy chunks: the entry JavaScript dropped from 710,229 B to 307,923 B (gzip ≈ 93 kB) and no chunk exceeds 500 kB, removing the Vite advisory reported in dev4.
- **Verification expansion.** CI now also runs a real-Docker sandbox integration job (digest-pinned image; success, output bounding, timeout/abort container cleanup, fail-closed without the image), a Windows launcher job (build, start, readiness, clean termination), and Playwright browser end-to-end tests against the built app and the mock upstream (profile setup, chat, settings keyboard behaviour, tool probe, automatic safe tool, approval and denial).

## Not verified

- The live Kaggle GPU endpoint, deployed model weights and its native tool round trip, the public tunnel, and the notebook's new checksum path on Kaggle hardware were not available for an end-to-end test. Tool capability on a real endpoint remains `not_verified` until the operator runs the harmless probe. The llama.cpp digests were verified against the GitHub API from this environment, and the checksum logic is unit-tested, but the full Kaggle download was not executed here.
- The model file is still fetched from Hugging Face `resolve/main` (unpinned revision) and `cloudflared` from the `latest` release URL; both are HTTPS downloads documented as residual risks because changing pinned model/tunnel defaults requires live-environment evidence.
- No Brave account/credential, live MCP server or external configured HTTP endpoint was exercised; missing-credential and failure paths are covered by tests.
- The DNS-pinning runtime was verified against real loopback sockets and injected DNS answers in unit tests and through the full CI suite, but not against a live rebinding domain.
- Real-browser coverage runs in Chromium via Playwright in CI; no assistive-technology audit and no other browser engines were exercised.
