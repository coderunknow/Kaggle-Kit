# Kaggle-Kit v0.1.0-dev4

**Status:** development prerelease.

- **Release tag:** `v0.1.0-dev4`
- **Source commit:** `{{SOURCE_SHA}}` (the exact commit this release was built from)
- **Compatibility:** ordinary OpenAI-compatible chat is preserved. Older profiles and conversations load with conservative, disabled tool defaults.

## What changed

- Added an opt-in, profile-scoped tool loop with calculator/conversion, conversation-scoped file reading, public web search and page retrieval, read-only endpoint diagnostics, optional Python sandbox, configured HTTP tools and remote MCP tools.
- Native tool support is model-, endpoint- and credential-specific. It is enabled only after a harmless probe verifies the function-call `finish_reason`, a synthetic tool-result follow-up and a final stop response. The probe never executes a function; unverified endpoints retain ordinary chat and do not receive tool definitions. Streamed tool-call fragments are probed separately (partial argument JSON is assembled per call index and only accepted with `finish_reason=tool_calls`) and reported as `streamingSupported`; tool rounds themselves use non-streaming requests so approvals can pause the loop.
- The recommended Qwen prompt now ships in two variants: the base text for ordinary chat without tools, and a derived tool-use variant (`qwen-selfhosted-tools-v1`) for verified profiles. The tool loop replaces the known no-tools sentence server-side so a tool list is never sent together with "you have no tools".
- Added server-side tool allowlists, argument/schema validation, bounded rounds/calls/time/I/O and upstream model-response bodies (1 MiB for tool chats, 16 KiB for probes), untrusted-output handling, single-use approvals, stale-approval invalidation, exact denied-operation replay refusal, cancellation and an accessible execution timeline. Writes, unknown permissions and every code run require per-call approval. Sandbox resource limits (timeout, memory, CPU, processes, output) and the tool input-size budget are configurable in Settings within server-enforced bounds.
- Added an in-memory, conversation-scoped upload vault (4 MiB upload and 100k extracted-character bounds; TXT, Markdown, CSV, JSON, text-based PDF and DOCX). There is no host-file browsing or host-code fallback.
- Added DNS-pinned public web/HTTP/MCP requests, redirect controls, SecretStore references for provider/header credentials, MCP review/grant invalidation, and browser-profile sanitization. Local MCP `stdio` execution is disabled.
- Upgraded the local SecretStore to v2 `{ version: 2, secrets, toolProfiles }`, with validated v1 migration, explicit profile CRUD, and secure file permissions. Clearing secret values intentionally preserves non-secret tool profile settings/references.
- Tool traces are not persisted by default. Legacy conversations without an explicit persistence setting lose stored traces/citations on load. Without confirmed Brave retention rights and an opt-in, search-derived assistant answers and later assistant replies are replaced with a clear placeholder in local storage and Markdown export.

## Not verified

- The Kaggle GPU endpoint, deployed model's native tool round trip (including a live streamed tool call), real `llama.cpp` response format, public tunnel and actual model weights were not available for an end-to-end test. Tool capability remains `not_verified` until the operator runs the harmless probe against the exact live profile.
- Public web/HTTP/MCP tools validate and pin public DNS addresses. The pre-existing OpenAI-compatible model proxy still applies host policy without DNS pinning; use an explicit host allowlist when that proxy is reachable by other local users.
- Docker is not installed in the validation environment. The Python sandbox remains disabled unless a pinned image and supported Docker runtime are configured; isolation has not been runtime-tested here.
- No Brave credential/account, account-specific retention rights or pricing, live MCP server, or external configured HTTP endpoint was tested. Provider credentials/terms and user authorization remain operator responsibilities.
- Browser accessibility was exercised through jsdom/component tests, not a real assistive-technology/browser audit; the Windows launcher was not exercised on Windows.
