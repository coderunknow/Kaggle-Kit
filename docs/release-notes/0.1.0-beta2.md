# Kaggle-Kit v0.1.0-beta2 — release candidate (not published)

**Status:** proposed beta candidate, prepared on top of `v0.1.0-beta1` and
merged into `main` as `19ea1b7` (via PR #25, which contained PR #24's commits).
This file is release-note input only; nothing here created a tag, a release or
a deployment.

- **Intended version:** `0.1.0-beta2`
- **Source commit:** `{{SOURCE_SHA}}` — **not yet resolved.** The rendering step
  of the release workflow substitutes the tagged commit; until a release is
  authorized there is no such commit, and no SHA is recorded here.
- **Compatibility:** storage and runtime formats are unchanged except for one
  additive field. Persisted assistant messages may now carry the *optional*
  boolean `streamUnverified` (`shared/domain.ts`); it is written only when a
  non-streamed answer had to explain itself and is omitted otherwise
  (`src/state/useChat.ts`). Conversations written by earlier versions load
  unchanged, a missing field is treated as absent (`src/lib/storage.ts`), and
  no migration or data rewrite is required. The profile, credential,
  tool-settings, approval and notebook runtime formats are unchanged. Tool
  permissions, bounds, approvals and fail-closed behaviour are unchanged.
  Verified by the legacy-payload and flag round-trip test in
  `src/lib/storage.test.ts` ("round trips the optional streamUnverified flag
  and defaults a legacy payload without it") and by the rendered-notice test in
  `src/components/App.test.tsx`; the serialized conversation format is
  therefore *extended*, not unchanged.

## Changes in this candidate

- **Streaming evidence instead of a boolean.** The streaming probe now records
  what it actually observed on the wire: total events, content events, the
  latency of the first content event, the total duration and the verification
  time. `diagnostics_check`, the connection test and the inference settings
  report these numbers and state explicitly that upstream event delivery does
  not prove proxy forwarding or browser rendering.
- **An answer that is requested without streaming says so.** A profile can
  keep `stream: true` as a saved preference, but the browser only requests a
  stream after this session verified it. The assistant message now records
  `streamUnverified` and the transcript explains why the answer arrived in one
  piece, instead of leaving the user to guess. Saving another inference
  parameter no longer clears the saved streaming preference, and a saved
  preference can always be switched off while it is unverified. The transcript
  notice and the single non-streaming retry after the proxy's `409` are covered
  by tests, including the guard that never retries once a delta has arrived.
- **Provider timeouts are reported as timeouts.** A streamed request that
  exceeded its timeout used to be reported as `499 cancelled`, because the
  server aborted its own upstream request. When the timeout happens before a
  response status has been sent, the proxy now answers `504` with an explicit
  message. Once the event stream has started, the status (`200`,
  `text/event-stream`) can no longer change: the timeout is reported as an
  in-band terminal `error` event carrying a machine code
  (`stream_timeout`, `client_cancelled`, `upstream_stream_failed`,
  `stream_event_too_large`). The browser derives the `ApiError.kind` from that
  fixed table — a real deadline becomes `timeout` with the timeout hint, other
  failures stay `inference` — and keeps the partial text instead of presenting
  it as finished. A terminal error is only trusted when it carries the random
  per-response marker the proxy also sends in the `x-kaggle-kit-stream-nonce`
  response header: the proxy forwards upstream event blocks verbatim, so an
  upstream that writes `{"error":{"code":"stream_timeout"}}` into its own
  stream must not be able to claim this proxy timed out or that the user
  cancelled. Such a payload stays an `inference` failure. Browser and proxy
  ship together, so the extra header is invisible to users. To guarantee that event is parseable, the proxy forwards
  only complete SSE event blocks and buffers an unterminated upstream frame;
  on failure it drops the partial frame and emits the terminal error on a clean
  boundary, with no `[DONE]` or `finish_reason`. A client still has to read the
  in-band event; the HTTP status alone cannot report every streamed timeout.
  `server/app.streaming.test.ts` now pins the status-less `504`, a timeout
  *inside* a partial frame, an upstream abort *inside* a partial frame and
  CRLF-framed incremental delivery.
- **Exact temperature conversions, including absolute zero.** Temperature is
  converted with the defining two-point relations of the scales instead of a
  shared absolute offset, so `32 °F → 0 °C`, `212 °F → 100 °C`,
  `100 °C → 212 °F` and `-459.67 °F → 0 K` are exact, while `-40`, decimals,
  aliases, whitespace and below-absolute-zero rejection keep their behaviour.
  The absolute-zero point is mapped directly: `-459.67 °F → -273.15 °C` is
  exactly `-273.15` (not `-273.15000000000003`), so chaining
  `°F → °C → K` works instead of being refused as below absolute zero, and
  `-273.15 °C → -459.67 °F` is exact in the other direction. Both Kelvin paths
  now use the defining 32 °F anchor, so `273.15 K → 32 °F` and
  `212 °F → 373.15 K` are exact too instead of `31.999999999999943` and
  `373.15000000000003`. Regression tests pin every defining anchor pair with
  exact equality, chained conversions, unit aliases, the justified tolerances
  for round trips, and the documented display rounding.
- **A real `files_analyze`.** The tool previously existed only in the catalog.
  It now reports the file's structure (line and character counts, CSV columns
  and **records**, JSON top-level shape), up to 20 literal case-insensitive
  matching lines and a bounded excerpt. CSV record counting is quote-aware, so
  a newline inside a quoted field no longer inflates `dataRows`; an
  unterminated quoted field is reported with `quoteClosed: false`. It answers
  nothing itself and refuses foreign conversations, empty questions and
  oversized questions. The result is sized from the effective per-tool output
  budget, including the untrusted-data prefix, so it stays valid JSON at every
  budget from 1 byte upwards: a wide-row file yields
  `excerptTruncated: true` (and `matchesTruncated: true` when matches are
  omitted), smaller budgets return progressively smaller complete `{note}`
  documents, and a budget that cannot hold any JSON object gets an explicitly
  labelled plain-text marker. A match list capped at 20 now carries
  `matchesTruncated: true` and `matchesFound: null` rather than looking like an
  exact count. Keyword extraction is Unicode-aware (NFC-normalized, letters,
  marks and numbers of every script) and samples at most six terms across the
  **whole** question, so a discriminating term at the end of a long Han, Kana
  or Hangul run is still searched; single-character CJK queries and short
  identifiers such as `c1` are kept. Every result carries a `query` diagnostic
  (`keywords`, `keywordsLimited`, `matchesEvaluated`, `scriptWindows`,
  `reason`, `note`): a stop-word-only question says the file was **not
  searched** instead of reporting `0 matching line(s)`.
- **Upload limit crash fixed.** A payload above the 4 MiB limit used to
  overflow the stack inside the base64 validation regular expression and
  surface as `HTTP 500 "The proxy failed to handle the request."`. The
  validation is now linear and canonical, and an oversized upload is a `400`
  with a reason. Regression test included.
- **Diagnostics separate every claim.** `diagnostics_check` returns a
  `verified` map (reachability, authentication, model listing, inference,
  streaming, native tool calling, reasoning-effort parameter and template),
  streaming evidence, and an explicit `notVerifiedByThisCheck` list, instead of
  a green summary that implies end-to-end streaming.
- **Tool-loop and browser tests.** The mock upstream can script file, web and
  conversion tool calls; the built-bundle integration harness now covers real
  uploads (CSV read/analyze, invalid ID, empty/unsupported/oversized upload),
  per-conversion tool results, and the claim-separated diagnostics. The one
  check that needs the public internet — a successful `web_open` retrieval
  against `pypi.org` — moved to the opt-in `npm run check:network`
  (`--network`); the deterministic default run keeps the refusal cases and is
  what CI, the nightly and the release workflow execute. Two new browser specs
  cover visible incremental streaming and an upload→`files_list`→`files_read`
  round trip.

## Independent-audit remediation (F1-F9)

An independent read-only review of PR #24 returned HOLD with nine verified
defects. This candidate now includes their fixes and regression tests:

- Framing-safe terminal SSE errors and structured error codes (F1/F5),
  including the race where an abort ends a read loop without throwing.
- Truthful `files_analyze` match/keyword truncation and diagnostics and a
  quote-aware CSV record count (F2/F3/F7).
- A budget-safe `files_analyze` fallback that never returns broken JSON (F4).
- `diagnostics_check` no longer claims authentication was verified for a
  keyless endpoint, and states the scope of `fullyVerified` (F6/C4).
- Exact Kelvin/Fahrenheit anchor conversions (F8).
- Head-specific release evidence, with each CI run's `head_sha` verified
  through the GitHub Actions API (F9). A streaming verification is also bound
  to the model that was probed and expires after the session's 10-minute
  capability-cache TTL, and the persisted `streamUnverified` notice is worded
  historically rather than as a claim about the current browser session
  (C1/C2).

Each fix has a regression test that was shown to fail when the original
behaviour was re-introduced in a throwaway copy of the tree.

## Verification boundaries

- No model endpoint or credential exists in the development environment, so
  real-model L2/L3 checks (live inference, live tool calling, a real model's
  prose about a tool result) remain **BLOCKED**. Everything in this candidate
  was verified with deterministic tests, the mock upstream, the real backend
  and the real file vault.
- The local sandbox cannot download a Playwright Chromium build (the browser
  CDN is not reachable), so the browser specs are **not** a local pass. They
  must be verified by the repository's hosted CI, which provisions Chromium.
- `web_open` was verified against reachable public hosts (`pypi.org`,
  `registry.npmjs.org`). Several other hosts fail in this environment because
  Node's bundled CA store rejects the sandbox's TLS interception with
  `ERR_UNABLE_TO_VERIFY_LEAF_SIGNATURE`; that is an environment limitation, not
  an application defect, and it is not the reported 12-second timeout.
- Docker-backed `code_execute` and the Windows launcher were not run locally.
