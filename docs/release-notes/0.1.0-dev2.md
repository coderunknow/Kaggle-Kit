# Kaggle-Kit v0.1.0-dev2

> The second prerelease of Kaggle-Kit. It turns the chat client of `dev1`
> into a full workspace and fixes the defects that the audit of this release
> found. The Kaggle deployment, the local proxy and the OpenAI-compatible
> request layer keep their behaviour and their data formats.

- **Release tag:** `v0.1.0-dev2`
- **Source commit:** `{{SOURCE_SHA}}` (the commit the tag points at, the exact
  SHA is also written into `manifest.json` and `verification-report.json`)
- **Release type:** prerelease
- **Automation:** `.github/workflows/release.yml` builds, verifies and uploads
  every asset of this release. No asset was uploaded by hand.

## What changed since v0.1.0-dev1

### The chat interface

The client was rebuilt around a conversation workspace instead of a settings
form with a chat box attached. It keeps the same storage keys, profile format
and request contract, so profiles and conversations of `dev1` keep working.

- **Sidebar.** The history is grouped by *Today*, *Yesterday*, *Previous 7
  days* and *Older*. Conversation rows are real buttons with an active state,
  an inline rename and a two-step delete. A search field appears with the
  third conversation and matches titles and message text. The active
  connection, its model and its state sit in the sidebar footer, so switching
  a profile no longer needs the settings drawer.
- **Context bar.** Title, message count, active profile and model, the result
  of the last connection test, the Markdown export and the theme switch.
- **Composer.** It grows with the text, keeps one draft per conversation
  (restored after a reload, removed on send), refuses to send during a
  generation, never interrupts an input method editor, and offers four
  editable prompt starters in an empty conversation.
- **Recovery on a refused stream.** When the proxy answers a streaming
  request with `409` because the transport was not verified in this session
  (for example after a restart), the client retries the same request without
  streaming *if no token arrived yet*. The message records that fallback; a
  request that already produced tokens is never repeated, so no answer can be
  duplicated.
- **Messages.** Markdown with GFM tables, syntax highlighted code blocks with a
  language label and a copy button, copy for the whole message, edit/resend,
  regenerate, retry, and a stop button. A reader who scrolls up is no longer
  dragged back by the stream; a *Jump to latest* button appears instead.
- **Truthful states.** A failed or cancelled answer is never marked complete,
  a broken stream keeps the part that arrived, `finish_reason` `length` and
  `content_filter` are shown, and token counts only appear when the server
  returned a `usage` object. Unsupported request parameters are still omitted
  instead of being guessed.
- **Export.** The active conversation can be downloaded as Markdown,
  including timestamps, roles, original Markdown, cancelled/failed markers and
  the reported token usage. The button reports it when the browser refuses the
  download instead of pretending it worked.
- **Settings drawer.** Four tabs (*Connections*, *Inference*, *Preferences*,
  *Data & credentials*) with a real tab list (arrow keys, Home, End), a focus
  trap, Escape handling and focus restoration. It separates the address of
  this page from the address of the model API, documents
  `KAGGLE_KIT_ALLOWED_HOSTS` including a PowerShell example, and states when
  the proxy has to be restarted.
- **Responsive and accessible.** The sidebar becomes a drawer below 1024 px,
  the status pill keeps only a dot below 560 px, and the layout reflows down
  to 360 px. Every control has an accessible name, the configuration is a tab
  list, state changes are announced in a visually hidden live region, and
  `prefers-reduced-motion` disables the animations. Shortcuts: **Alt+Shift+N**
  for a new conversation and **Ctrl/Cmd+/** to focus the composer.

### Fixed defects (each covered by a test)

1. **Drafts were not preserved.** The composer kept one text for every
   conversation in memory, so switching conversations carried the text along
   and a reload lost it. Drafts are now per conversation and stored locally.
2. **Ctrl+Enter could not send.** With the preference *Ctrl+Enter to send*,
   only a plain Enter was handled, which inserted a newline. The modifier is
   handled now, and an active input method editor is never interrupted.
3. **A truncated stream looked complete.** A stream that ended without a
   finish reason was returned as a successful answer, and an error event in
   the middle of a stream was ignored. Both now fail the request while keeping
   the text that arrived.
4. **The first message of a landing-page conversation could be lost.** It is
   queued and sent once the new conversation exists in state.
5. **Test/Discover wrote the key into the proxy secret store before Save.** A
   key that the user typed but did not save stayed on disk. Saving is now the
   only write; testing uses the typed key for that one request.
6. **Editing a saved profile silently changed the active profile.** Only a new
   profile becomes active; editing keeps the current selection.
7. **Streaming capability was cached per base URL only.** A second profile on
   the same host with a different key, or a rotated key, could inherit a
   streaming verification made with another credential. The cache is now keyed
   by endpoint and a SHA-256 hash of the key (never the key itself) and is
   bounded.
8. **The transcript was force-scrolled during a stream.** Reading an earlier
   answer was interrupted by every token. The view follows only while the
   reader is at the bottom and offers *Jump to latest* otherwise.
9. **Row actions disappeared while an answer streamed.** Copy, edit, resend
   and retry stayed hidden because a pending request was treated as a global
   lock. They are available on every finished message again.
10. **`/api/health` returned the configured allow list.** It now returns only
    `{ok, name}`.
11. **The settings drawer lost and re-ran its focus effect on every render.**
    The close handler is stable; focus restoration runs once per open.
12. **The status pill collided with the title on small screens.** It collapses
    to a dot below 560 px.
13. **The message list had no id for its navigation label.** The sidebar and
    the message region are now properly labelled, and the mobile drawer can be
    closed with Escape.

### Tests and tooling

- 24 test files, **202 tests** in total (was 155 in 16 files). New coverage:
  gateway error/abort/incomplete handling, draft storage, prompt starters,
  Markdown and code-block copy, export, the settings drawer (focus, Escape, tab
  keys, connection help), the sidebar grouping, the focus trap, the capability
  cache and the chat surface itself.
- The integration check still drives the built application against a mock
  upstream: 14 of 14 checks.
- All version references are `0.1.0-dev2`, including the lockfile, the release
  tooling, the tests and the documentation.

### Unchanged on purpose

- No new runtime dependency, no second API client, no parallel configuration
  store. The CSS design tokens stay; the new components use them.
- Upstream requests still include the model, the messages, `max_tokens`,
  `temperature` and `top_p`, add penalties only when enabled, and send
  `reasoning_effort` and `stream` only when the endpoint advertised or
  verified them. Start-up options of the server are still displayed separately
  and never sent.
- The proxy security defaults are unchanged: loopback bind, origin check,
  JSON-only bodies, redirect refusal, path containment, no key in a log line
  or a URL.

## Installation and start

The application bundle has no runtime dependencies, it needs Node.js 22 or
newer:

```bash
unzip v0.1.0-dev2-app.zip
cd kaggle-kit-app   # the directory of the extracted archive
node dist/server/index.js
```

The backend serves the built client and the API on `http://127.0.0.1:8787`.
Open that address in a browser, open the settings drawer and enter the base URL
and the API key of the server. The environment variables `KAGGLE_KIT_PORT`,
`KAGGLE_KIT_HOST`, `KAGGLE_KIT_ALLOWED_HOSTS` and
`KAGGLE_KIT_BLOCK_PRIVATE_NETWORKS` change the defaults; they are read at
start-up, so the proxy has to be restarted after a change.

For the deployment on Kaggle, open the notebook of this release in a GPU
runtime and run the cell. It prints the public URL and the path of the file
with the API key. The Quick Tunnel is temporary and does not support server
sent events, so the application has to be used in the non streaming mode.

The complete documentation is in `README.md`, `docs/security.md`,
`docs/kaggle-deployment.md`, `docs/chat-interface.md` and
`docs/troubleshooting.md` of the source archive.

## Not verified

The following points were **not** verified for this release. They are stated
here so that nobody reads the automated tests as a proof for them.

- The browser interface in a real browser. Component tests run in jsdom; no
  Chromium or Firefox was available in the build environment, so layout,
  font rendering, real scroll behaviour and the visual result of the new
  components were not verified in a browser.
- The Kaggle GPU runtime, the download of the model, the real llama.cpp
  inference and the answers of the model. The tests of the notebook use stubs
  and a local mock server.
- The Cloudflare Quick Tunnel, the public endpoint and the reachability of the
  public URL from outside.
- The behaviour of the deployment script on a machine that does not have the
  tools of the Kaggle image.
- The effect of the multi token prediction option on the quality of the
  answers and on the speed. The option is only reported as applied when the
  server confirms it.

## Known limits of the design

- The proxy binds to the loopback interface. Every program on the machine can
  use it. The origin check protects against cross site requests from a
  browser, it is not an authentication.
- The upstream is not restricted by default; the allow list of the hosts
  (`KAGGLE_KIT_ALLOWED_HOSTS`) has to be set explicitly. A name that is
  allowed can be changed by DNS after the check, so the allow list does not
  protect against DNS rebinding.
- The secrets of the server are stored in a file on the machine, they are
  never sent to the browser, but the file is not encrypted.
- The Quick Tunnel is temporary and public. Everyone who knows the URL and the
  key can use the server until the session ends.
- A conversation export is written by the browser; the application cannot
  revoke or delete the file afterwards.
