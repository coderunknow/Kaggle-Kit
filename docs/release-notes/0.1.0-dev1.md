# Kaggle-Kit v0.1.0-dev1

> The first prerelease of Kaggle-Kit. It contains the Kaggle deployment of a
> local llama.cpp server, the browser chat client for it and the local proxy
> between the two. Everything that is not covered by an automated check is
> listed under "Not verified" below.

- **Release tag:** `v0.1.0-dev1`
- **Source commit:** `{{SOURCE_SHA}}` (the commit the tag points at, the exact
  SHA is also written into `manifest.json` and `verification-report.json`)
- **Release type:** prerelease
- **Automation:** `.github/workflows/release.yml` builds, verifies and uploads
  every asset of this release. No asset was uploaded by hand.

## What this release contains

- `notebooks/qwen3_8_27b_api.py` - the Kaggle cell. It downloads and verifies
  the llama.cpp binaries and the GGUF model, generates the API key, stores it
  in `api_key.txt` (mode 0600), starts the server, opens a Cloudflare Quick
  Tunnel and verifies the public endpoint with a real chat completion before
  it prints the URL. The script is shipped as the notebook
  `v0.1.0-dev1-notebook.ipynb`.
- The browser client: a chat interface with a connection test, a streaming
  and a non streaming mode, the history of the conversations and a settings
  dialog for the base URL, the API key and the model.
- The local proxy (`server/`): it keeps the API key out of the browser, checks
  the origin of a request, restricts the upstream hosts and forwards the
  stream of the answer.
- The prompt research of `research/qwen-system-prompt/` and the optimized
  Qwen system prompt that the client can insert with one click.

## Security and reliability fixes

The fixes of this prerelease were found by a review of the diff of the pull
request and are covered by regression tests.

- **Path traversal in the static file server.** The requested path is now
  resolved inside the client directory. Neither `..` nor its percent encoded
  forms can leave the directory any more.
- **Redirects of the upstream.** The client refuses a redirect to another
  origin when a key is set, and the server does not follow a redirect of the
  upstream any more - neither in the request nor in the stream. A redirect can
  no longer send the prompt and the key to a host that is not allowed to see
  them.
- **Cancelling a stream.** A disconnect of the browser cancels the request to
  the upstream. The connection is not held open any more and the cancellation
  is reported to the client instead of ending the stream silently.
- **The origin of a request.** A request from a page of another origin is
  refused, and a body that is not JSON is refused. This is protection against
  cross site requests; it is not an authentication.
- **The download in the notebook.** The archives of the binaries and the model
  are extracted safely, an entry of an archive can no longer write outside of
  the target directory, and the download is verified before it is used.
- **The key of the server.** The key is written to a file that only the owner
  can read and is generated again when the server is restarted, so a key of an
  earlier session cannot be used.
- **The public endpoint.** The notebook verifies the public URL with a real
  chat completion before it reports it as working.
- **The multi token prediction option.** The option is only reported as active
  when the server has really applied it. A smoke test with the normal
  inference does not prove the effect of the option.

## Installation and start

The application bundle has no runtime dependencies, it needs Node.js 22 or
newer:

```bash
unzip v0.1.0-dev1-app.zip
cd kaggle-kit-app   # the directory of the extracted archive
node dist/server/index.js
```

The backend serves the built client and the API on `http://127.0.0.1:8787`.
Open that address in a browser, open the settings dialog and enter the base
URL and the API key of the server. The environment variables
`KAGGLE_KIT_PORT`, `KAGGLE_KIT_HOST`, `KAGGLE_KIT_ALLOWED_HOSTS` and
`KAGGLE_KIT_BLOCK_PRIVATE_NETWORKS` change the defaults.

For the deployment on Kaggle, open the notebook of this release in a GPU
runtime and run the cell. It prints the public URL and the path of the file
with the API key. The Quick Tunnel is temporary and does not support server
sent events, so the application has to be used in the non streaming mode.

The complete documentation is in `README.md`, `docs/security.md`,
`docs/kaggle-deployment.md`, `docs/chat-interface.md` and
`docs/troubleshooting.md` of the source archive.

## Not verified

The following points were **not** verified for this release. They are stated
here so that nobody reads the automated tests as a proof for them.

- The Kaggle GPU runtime, the download of the model, the real llama.cpp
  inference and the answers of the model. The tests of the notebook use
  stubs and a local mock server.
- The Cloudflare Quick Tunnel, the public endpoint and the reachability of the
  public URL from outside.
- The behaviour of the browser interface in a real browser. The component
  tests run in jsdom, not in a browser.
- The effect of the multi token prediction option on the quality of the
  answers and on the speed. The option is only reported as applied when the
  server confirms it.
- The behaviour of the deployment script on a machine that does not have the
  tools of the Kaggle image.

## Known limits of the design

- The proxy binds to the loopback interface. Every program on the machine can
  use it. The check of the origin protects against cross site requests from a
  browser, it is not an authentication.
- The upstream is not restricted by default, the allow list of the hosts
  (`KAGGLE_KIT_ALLOWED_HOSTS`) has to be set explicitly. A name that is
  allowed can be changed by DNS after the check, so the allow list does not
  protect against DNS rebinding.
- The secrets of the server are stored in a file on the machine, they are
  never sent to the browser, but the file is not encrypted.
- The Quick Tunnel is temporary and public. Everyone who knows the URL and the
  key can use the server until the session ends.
